# nodejs-hw — Notes API

Навчальний Express-додаток із MongoDB та Mongoose. Підтримує створення, читання,
оновлення та видалення нотаток. Код розділено на модель, контролери, маршрути,
підключення до бази та middleware. Локальний каталог проєкту — `notes-api`;
файли призначені для продовження роботи в репозиторії `nodejs-hw`.

## Запуск

Використайте Node.js 24 та npm. Відкрийте термінал у папці `notes-api`:

```sh
npm ci
```

Якщо `.env` відсутній, скопіюйте `.env.example` у `.env`. У PowerShell:

```powershell
Copy-Item .env.example .env
```

У Linux/macOS:

```sh
cp .env.example .env
```

Заповніть у `.env` дві змінні, зберігаючи їхні назви:

```dotenv
PORT=3000
MONGO_URL=mongodb+srv://USERNAME:PASSWORD@YOUR_CLUSTER.mongodb.net/nodejs-hw
```

Замість шаблонних значень використайте власний рядок підключення MongoDB Atlas.
Назва бази у шляху URI — `nodejs-hw`, назва колекції — `notes`. У налаштуваннях
Atlas користувач бази має мати доступ до цієї бази, а IP комп’ютера — бути
дозволеним у Network Access. `.env` не додається до Git; `.env.example` містить
лише шаблон без облікових даних.

У локальному каталозі `.env` уже налаштований. До ZIP-архіву файл `.env`
з обліковими даними не включено; після розпакування створіть його за шаблоном
і заповніть власні налаштування.

```sh
npm run dev
```

`npm run dev` запускає сервер через nodemon із перезапуском після змін.
`npm start` запускає сервер через Node.js. Для зупинки натисніть `Ctrl+C`.

Сервер починає слухати HTTP-запити лише після успішного `connectMongoDB()`.
При підключенні до бази у терміналі з’являється:

```text
✅ MongoDB connection established successfully
```

Адреса за стандартних налаштувань — `http://localhost:3000`. Якщо `PORT`
не задано, використовується 3000. Змінні, задані в середовищі запуску, мають
пріоритет над `.env`. Без `MONGO_URL` або при невдалому підключенні сервер
завершує запуск із помилкою.

## Маршрути

| Запит                   | Контролер     | Статус | JSON-відповідь          |
| ----------------------- | ------------- | ------ | ----------------------- |
| `GET /notes`            | `getAllNotes` | 200    | Масив усіх нотаток      |
| `GET /notes/:noteId`    | `getNoteById` | 200    | Знайдена нотатка        |
| `POST /notes`           | `createNote`  | 201    | Створена нотатка        |
| `PATCH /notes/:noteId`  | `updateNote`  | 200    | Нотатка після оновлення |
| `DELETE /notes/:noteId` | `deleteNote`  | 200    | Видалена нотатка        |

Відповіді містять безпосередньо масив або об’єкт нотатки, без обгортки `data`.
Порожня колекція повертається як `[]`. У `:noteId` передавайте MongoDB `_id`,
отриманий у відповіді сервера. За умовою цього етапу формат ObjectId окремо
не перевіряється.

Поля нотатки:

- `title` — обов’язковий рядок; пробіли на початку й у кінці обрізаються.
- `content` — необов’язковий рядок із такими самими правилами обрізання;
  значення за замовчуванням — `""`.
- `tag` — необов’язковий рядок; значення за замовчуванням — `"Todo"`.
  Дозволено `Work`, `Personal`, `Meeting`, `Shopping`, `Ideas`, `Travel`,
  `Finance`, `Health`, `Important`, `Todo`.
- `_id` створює MongoDB, а `createdAt` і `updatedAt` додає Mongoose завдяки
  `timestamps: true`.

Для POST і PATCH використайте заголовок `Content-Type: application/json`.
Приклад створення:

```http
POST /notes HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "title": "Підготувати домашнє завдання",
  "content": "Перевірити CRUD-маршрути",
  "tag": "Todo"
}
```

Приклад часткового оновлення (замініть ID на `_id` створеної нотатки):

```http
PATCH /notes/507f1f77bcf86cd799439011 HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{
  "tag": "Important"
}
```

PATCH змінює лише передані `title`, `content` і `tag`, зберігаючи решту полів.
Валідація Mongoose увімкнена також для оновлень. Відповідь містить оновлену
нотатку, а не її попередній стан.

## Помилки та middleware

Якщо GET, PATCH або DELETE не знаходить нотатку за валідним ID, відповідь
має статус 404:

```json
{ "message": "Note not found" }
```

Невідомий маршрут повертає статус 404:

```json
{ "message": "Route not found" }
```

Тестовий маршрут `/test-error` вилучено; запит до нього тепер також повертає
`Route not found`.

Помилки перевірки моделі Mongoose повертають 400. Помилки з HTTP-статусом,
зокрема створені через `http-errors`, зберігають свій статус. Інші помилки
повертають 500. Формат відповіді завжди `{ "message": "повідомлення помилки" }`.

`pino-http` логує HTTP-запити в терміналі у форматі JSON. `pino-pretty` збережено
в `devDependencies`, але автоматичне перетворення логів на текст не увімкнено.
`cors()` дозволяє запити з інших доменів; `express.json()` обробляє JSON-тіла.
Після маршрутів зареєстровано `notFoundHandler`, а останнім — `errorHandler`.
Express 5 передає помилки асинхронних контролерів до глобального обробника.

## Імпорт початкових нотаток

Файл `notes.json` містить 40 наданих навчальних записів. Усі 40 записів уже
імпортовано через Mongoose в `nodejs-hw.notes` за погодженням користувача.
Точні збіги перевірено перед додаванням; повторного створення наявних записів
не виконувалось. `GET /notes` підтвердив наявність усіх 40 нотаток, зокрема
полів `createdAt` та `updatedAt`.

Імпорт через UI замінено програмним після того, як Computer Use не зміг
надійно визначити URL сторінки в Opera. Для імпорту в іншу, порожню колекцію
через Compass використайте такі кроки (поточний набір повторно імпортувати не потрібно):

1. Підключіться, використовуючи свій `MONGO_URL`.
2. Відкрийте базу `nodejs-hw` та колекцію `notes`. Якщо їх ще немає, створіть їх
   із цими точними назвами.
3. Виберіть **Add Data → Import JSON or CSV file**, формат **JSON**, а потім
   файл `notes.json` та **Import**.
4. Переконайтеся, що документи з’явилися в `nodejs-hw.notes`, і виконайте
   `GET /notes` після запуску сервера.

Назва колекції `notes` явно задана в моделі. Імпорт через Compass не викликає
Mongoose, тому його defaults, trim і timestamps застосовуються до операцій
через застосунок, а не до самого імпорту.

## Перевірка якості

```sh
npm run lint
npm run format:check
```

ESLint використовує базову flat-конфігурацію з рекомендованими правилами
та глобальними змінними Node.js. Ці команди перевіряють код і форматування;
для перевірки підключення та CRUD потрібен запущений сервер із доступною MongoDB.

Під час перевірки з реальною MongoDB Atlas успішно виконано всі п’ять
CRUD-операцій. Перевірено значення за замовчуванням, обрізання пробілів,
timestamps, валідацію PATCH, відповіді 404 і 500, статус 400 для некоректного
JSON, CORS та логування через pino-http. Тимчасову тестову нотатку видалено;
інші записи не змінювалися.

У середовищі перевірки Node.js використовував локальний DNS `127.0.0.1`,
на якому не працювала DNS-служба, тому SRV-запит повертав `ECONNREFUSED`.
Лише для процесів перевірки й імпорту задано DNS `1.1.1.1` і `8.8.8.8`.
Код проєкту й системні налаштування DNS не змінювалися.
Після імпорту додатково перевірено, що `GET /notes` повертає всі 40 записів
із `notes.json` з точними значеннями `title`, `content` і `tag`.

[Mongoose: валідація](https://mongoosejs.com/docs/validation.html),
[Mongoose: оновлення документа](https://mongoosejs.com/docs/tutorials/findoneandupdate.html).
